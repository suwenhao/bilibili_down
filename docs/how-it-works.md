# BiliDown 工作原理简述

这份文档面向普通用户，简单说明 BiliDown 为什么需要网络、本地数据库、下载引擎和媒体处理组件。

## 基本流程

1. 你输入或确认一个 B 站链接。
2. BiliDown 向 B 站接口请求视频信息和可下载资源。
3. 你选择分集、画质、音质和附加内容。
4. 应用把任务保存到本地数据库。
5. 下载引擎把视频流、音频流、封面、字幕或弹幕保存到本机。
6. 需要合并时，应用使用 FFmpegKit / FFmpeg 在本机完成处理。
7. 完成后，文件会移动到你设置的下载目录。

## 下载状态

任务一般会经过这些状态：

- 待下载：已经加入队列，还没有开始。
- 解析中：正在刷新播放地址和资源信息。
- 下载中：正在保存视频、音频或附加资源。
- 等待合并：媒体分流已下载完成，等待进入合并。
- 合并中：正在生成最终文件。
- 已下载：最终文件已经生成。
- 暂停、失败或取消：任务被用户操作或异常中断。

应用会把任务状态保存到本地数据库，重启后会尽量恢复可继续处理的任务。

## 各平台差异

| 平台 | 下载与后台能力 |
| --- | --- |
| Android | 使用前台服务和系统任务能力维持下载；系统可能限制长时间后台运行。 |
| iOS | 使用系统后台下载能力；如果用户强制划掉应用，后台处理可能被系统终止。 |
| Windows x64 | 使用桌面进程、aria2 和系统文件管理器能力。 |
| Linux x64 | 使用桌面进程、aria2 和系统文件管理器能力。 |
| macOS | 使用桌面进程、aria2、系统通知和文件管理器能力。 |

不同系统对后台、通知、文件目录和权限的限制不同，所以实际表现可能略有差异。

## 登录和权限

未登录时，应用只能读取游客可访问的信息和清晰度。登录后，应用会用当前账号 Cookie 请求账号有权访问的内容，例如更高清晰度、历史记录、收藏夹和最近点赞。

BiliDown 不提供会员权限提升、地区限制绕过或 DRM 破解。接口返回什么资源，应用就只处理这些资源。

## 本地文件

下载过程可能会先生成临时文件，合并完成后再移动为最终文件。已下载页面和详情页记录的是本地文件索引，方便你打开目录、转换格式或删除记录。

如果你手动移动或删除了文件，应用中的记录可能需要刷新或重新处理。
